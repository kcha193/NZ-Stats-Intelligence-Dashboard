# Phase 2A: Electronic Card Transactions implementation plan

**Goal:** Ingest and reconcile official ECT releases and expose a dedicated research dashboard.
**Architecture:** Extend the adapter registry and existing transactional ingestion, scheduler,
vintage store, API and chart infrastructure. Snapshot series definitions per vintage with an additive
database migration. Use the full official CSV ZIP as the primary source; cross-check embedded charts.
**Stack:** Existing Python/FastAPI/SQLite and React/TypeScript/ECharts; no new runtime dependencies.
**Execution:** Inline, autonomous, focused TDD; no subagents, merge or deployment.
Kevin subsequently requested committing, pushing and opening a new pull request.

## Constraints and review focus

- Keep the ten-second shared request pacing and raw artifacts. Use official captured fixtures offline.
- Preserve migration calculations and database compatibility; metadata reads must follow the vintage.
- Monthly and quarterly source series, adjustments, units and industries must remain distinct.
- Missing/suppressed values stay missing. Incompatible or malformed bundles fail before commit.
- Independently adjusted industries need not add to totals. History from one file is one vintage.
