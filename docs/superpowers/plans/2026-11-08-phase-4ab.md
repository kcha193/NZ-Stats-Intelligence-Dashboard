# Historical AI summary remediation implementation plan

> **For agentic workers:** Use superpowers:executing-plans for backend and evidence work; use superpowers:dispatching-parallel-agents for the independent frontend workstream.

**Goal:** Promote only claims without automated errors, retaining warnings, original output and historical verification.

**Architecture:** Keep the existing internal eligibility gate and original API fields. Add an on-demand `verify-5` assessment, bound to the original output hash, and a deterministic set of executive, warning and excluded claim paths. Render only eligible assessment claims in highlights; keep original claims and both assessments accessible locally.

**Tech stack:** Existing Python/FastAPI/SQLite and React/TypeScript stack; no new dependency.

**Spec:** Owner's Phase 4AB request, recorded in the resulting `docs/phase-4ab-historical-ai-remediation.md`.

## Global constraints

- No hosted AI provider, retry, inference, production write, permission change, publication or merge.
- Keep `verify-4` and `verify-5` unchanged unless a demonstrated defect requires separately versioned `verify-6`.
- Private source text, model output and diagnostic HTML stay in ignored `data/phase-4ab/`.
- Original verdict, provenance, spending, counters and claim evidence remain intact.
- No human approval required for internal viewing; all existing local-only checks remain.

## Review focus

- Nested evidence errors exclude their containing claim; unknown/global errors fail closed.
- Failed outlook never appears through another card or historical preview.
- Warnings remain warnings; missing units never acquire an invented currency.
- Assessment identity binds output, document evidence, verifier and assessment time.
- Public/static paths never request or receive internal commentary.
